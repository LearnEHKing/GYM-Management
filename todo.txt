6. High | Business Logic | Zero-day trials create invalid records

member.membership_expiry = join_date - relativedelta(days=1)
member.membership_active = False

but still creates a “Trial” membership record.

Scenario: A member with no trial appears in payment history, has an expiry before joining, and may be treated inconsistently by reports and reminders.

Fix: Either reject zero-day trials or create an explicitly inactive record with clear semantics. Prefer:
if trial_days == 0:
    member.membership_expiry = None
    member.membership_active = False
else:
    member.membership_expiry = join_date + relativedelta(days=trial_days - 1)
    member.membership_active = True

7. High | Business Logic | Active counter is not continuously reconciled
The counter is initialized only when the column is first added in main.py:126. It can later drift because of concurrent updates, failed deployments, manual SQL, or older code paths.

Scenario: The UI shows 49 active members while the counter says 50, blocking valid additions or allowing over-capacity additions.

Fix: Add a periodic reconciliation job and alert on mismatch
UPDATE gym_owner owner
SET active_member_count = (
    SELECT COUNT(*)
    FROM member
    WHERE member.owner_id = owner.id
      AND member.membership_active = TRUE
);
Better still, use a transactionally protected capacity table or database trigger.
